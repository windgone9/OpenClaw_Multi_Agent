LiteLLM 负载均衡分析
请求类型 经过 LiteLLM? 负载均衡方式 实际路径
纯文本对话 是 LiteLLM 负载均衡 Nginx → Hermes → LiteLLM → Ollama
图片理解 (Vision) 是 LiteLLM 负载均衡 Nginx → Hermes → Stream → LiteLLM → Ollama
语音识别 (HTTP ASR) 否 直连 FunASR Nginx → Hermes → Stream → FunASR
流式语音转写 (WS ASR) 部分 ASR 直连, LLM 经 LiteLLM Nginx → Stream → FunASR (ASR) + LiteLLM (LLM)
多模态混合 是 LiteLLM 负载均衡 Nginx → Hermes → Stream → LiteLLM → Ollama
Embedding 是 LiteLLM 负载均衡 Nginx → LiteLLM → Ollama
MinIO 预签名 否 Stream Svc 直连 Nginx → Stream → MinIO

🔗 统一入口 API — POST /v1/chat

前端只需调用一个端点，根据 type 字段自动路由到对应后端服务。 type 缺失时根据 attachments 自动推断。

type: "chat"
{"type":"chat", "messages":[...], "model":"qwen2.5"}
type: "vision"
{"type":"vision", "messages":[...], "model":"auto"}
type: "asr"
{"type":"asr", "file":"http://minio/audio.wav"}
type: "multimodal"
{"type":"multimodal", "prompt":"描述图片", "attachments":[...]}
type: "stream_asr"
{"type":"stream_asr", "auto_llm":true, "model":"qwen2.5"}
自动推断 (无 type)
{"messages":[...], "attachments":[ {"type":"image","url":"..."} ]}
Nginx 三大核心角色
1. 统一入口 & 反向代理
前端只需访问 localhost:8080，Nginx 按路径路由到不同后端服务，隐藏内部拓扑。
2. 负载均衡
least_conn — 对话/路由 (长请求最少连接)
ip_hash — WebSocket (会话亲和，连接保持)
least_conn — Hermes Agent
3. 协议适配
WebSocket 升级 (Upgrade 头)
SSE 流式 (proxy_buffering off)
大文件上传 (client_max_body_size 100m)
