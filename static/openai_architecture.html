🔀 请求流路径 — 每个场景的完整链路

1 Chat — OpenAI 兼容 ✅ POST /v1/chat/completions {model, messages, stream}
Client (OpenAI SDK) → Nginx :8090 → Proxy :4000 → LiteLLM :4000 → Ollama qwen2.5
Proxy 预处理: 解析 ChatCompletionRequest → 检查 attachments (无) → 检查 vision (无) → 转发 LiteLLM
from openai import OpenAI client = OpenAI(base_url="http://localhost:8090/v1", api_key="sk-litellm-local") r = client.chat.completions.create( model="qwen2.5", messages=[{"role": "user", "content": "你好"}], stream=True )
2 Vision — OpenAI 兼容 ✅ POST /v1/chat/completions {content:[{type:image_url}]}
Client → Nginx → Proxy ① vision检测 → 自动切换llava ② 下载图片URL → base64 → LiteLLM → Ollama llava:7b
Proxy 预处理: 检测 content 含 image_url → model 自动切换 llava → 外部 URL 下载 → base64 编码 → 构建 Ollama images 格式
r = client.chat.completions.create( model="qwen2.5", # 自动切换 llava messages=[{"role": "user", "content": [ {"type": "text", "text": "描述这张图片"}, {"type": "image_url", "image_url": {"url": "http://minio/img.png"}} ]}] )
345 PDF/Word/Audio Attachment — OpenAI 兼容 ✅
Client → Nginx → Proxy attachments预处理 → LiteLLM → Ollama qwen2.5
PDF: PDF URL → PyMuPDF 提取文本 → 替换 prompt
extra_body={"attachments": [{"type":"pdf", "url":"http://minio/doc.pdf"}]}
Word: DOCX URL → python-docx 提取文本 → 替换 prompt
extra_body={"attachments": [{"type":"word", "url":"http://minio/doc.docx"}]}
Audio: Audio URL → 下载 → FunASR ASR → 文本替换 prompt
extra_body={"attachments": [{"type":"audio", "url":"http://minio/audio.wav"}]}
6 ASR — OpenAI 兼容 ✅ POST /v1/audio/transcriptions
Client → Nginx → Proxy → FunASR SenseVoice fallback: Doubao → Ollama Whisper
两种模式:
JSON URL 模式: {file: "http://minio/audio.wav"} → Proxy 下载音频 → FunASR/Doubao/Whisper 级联
multipart 模式: 直接上传文件 → Proxy 转发到 FunASR 本地 ASR
# JSON URL 模式 r = requests.post("http://localhost:8090/v1/audio/transcriptions", json={"file": "http://minio:9000/openclaw/audio.wav"}) # multipart 模式 (OpenAI SDK) with open("audio.wav", "rb") as f: r = client.audio.transcriptions.create(model="funasr", file=f)
7 Multimodal — OpenAI 兼容 ✅ POST /v1/chat/completions {content:[text+image_url]}
Client → Nginx → Proxy vision检测→llava → LiteLLM → Ollama llava
与 Vision 流程相同: 多模态 = Chat + Vision content 格式合并。图片自动路由到 llava，音频自动路由到 ASR → 文本。
r = client.chat.completions.create( model="qwen2.5", messages=[{"role": "user", "content": [ {"type": "text", "text": "多模态端到端测试"}, {"type": "image_url", "image_url": {"url": "http://minio/img.png"}} ]}] )
8 WS Chat — 自定义协议 ❌ WS /v1/stream/ws
Client (WebSocket) → Nginx (WS Upgrade) → Stream Service :8084 文本路径: LiteLLM→Ollama 音频路径: FunASR→ASR → LiteLLM→LLM回复
双向实时对话: 发送文本 {type:"text",content:"你好"} → llm_chunk 流式回复
发送二进制音频 → ASR 转写 → asr_text → LLM 流式回复
⚠️ OpenAI 无 WebSocket 标准协议，需直接 WebSocket 调用
9 WS ASR — 自定义协议 ❌ WS /v1/stream/asr
Client (WS) → Nginx (WS Upgrade) → Stream :8084 PCM缓冲→_pcm_to_wav() → FunASR ASR 级联 auto_llm ≥2 ASR结果 → LiteLLM→Ollama LLM
PCM 推流流程: connected → config → config_ack → PCM 分块推流 (16kHz 16bit mono) → asr_partial 中间结果 → auto_llm 边听边答 → stop → asr_final → LLM 最终回复
⚠️ OpenAI 无流式 ASR 标准协议
10 MinIO Presign — 自定义 ❌ POST /v1/minio/presign
Client → Nginx → Proxy → MinIO :9000
Presigned URL 生成: {bucket, key} → MinIO AWS4-HMAC-SHA256 签名 → 返回可公开访问的临时 URL
用于 Dashboard 文件上传: 先获取 presigned URL → 上传文件到 MinIO → 在请求中引用 URL

🎯 关键架构设计

Proxy Pod — 唯一 LLM API 入口
所有 OpenAI 兼容请求经 Nginx 路由到 Proxy (:4000)。Proxy 负责预处理 (附件→文本、图片→base64、音频→ASR) 再转发到 LiteLLM。

好处: 预处理能力对所有请求生效，Nginx 路由更简单，LiteLLM 不直接对外。
LiteLLM CLI — 模型路由网关
LiteLLM CLI Pod (:4000) 负责实际模型推理路由: 本地模型 → Ollama, 云模型 → DeepSeek/Moonshot。

策略: latency-based-routing (延迟优先) + 2 retries + 60s cooldown。
不对外直接暴露，仅接受 Proxy 和 Stream 内部调用。
Stream Service — 实时推流
Stream Service (:8084) 处理所有 WebSocket 和 SSE 推流。ip_hash upstream 保证 WebSocket 会话粘性。

auto_llm: ws_asr 累积 ≥2 个 ASR 结果后自动触发 LLM，实现边听边答。
限制: OpenAI 无 WS 标准，这 3 个功能无法兼容。
Hermes — 任务调度 + 自学习
Hermes (:8082) 专注 K8S 任务调度，不再是 LLM 预处理入口。`/v1/chat` 预处理功能已迁移到 Proxy Pod。

自学习: MEMORY.md 闭环 — 路由→执行→反馈→规则演化→下一轮。
4 worker: 队列调度，信号量控制 GPU 并发。
Nginx — 统一入口 + 负载均衡
单一外部入口 (:8090)，按 URL 路径分发: `/v1/*` → Proxy, `/v1/stream/*` → Stream, `/k8s/*` → Hermes, `/ui/*` → LiteLLM UI。

协议适配: WebSocket Upgrade + SSE no-buffering + 大文件上传。
auth注入: LiteLLM UI 路径自动注入 Bearer token。
ASR 级联 — 3 层 Fallback
① FunASR (本地 SenseVoice) — 优先
② Doubao (豆包云 ASR) — 需要 API Key
③ Ollama Whisper (本地 fallback) — 最后

PCM→WAV: Stream Service 的 _pcm_to_wav() 包装 44 字节 WAV 头。
