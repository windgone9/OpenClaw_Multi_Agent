1. 概述

OpenClaw Multi-Agent 是 LLM 请求多智能体调度系统。当前部署在测试服务器 192.168.0.151（4×H100），以 K8S 形式运行：OpenClaw 自身 pod（proxy / stream-service / funasr / hermes / minio / nginx）+ 复用现有 LiteLLM（lite-helm-litellm），推理后端为 GPUStack 托管的 vLLM（集群外，两模型常驻 tp2）。

对外统一入口为 nginx NodePort 30080，请求链路：客户端 → nginx(:30080) → proxy(预处理) → litellm(路由) → GPUStack vLLM。proxy 提供附件预处理、图片自动切视觉模型、ASR 级联等增强能力，兼容 OpenAI API。

服务模型能力状态后端适用场景
文本推理deepseek-r1-distill-qwen-32b文本可用GPUStack vLLM (2×H100, tp2)推理、代码、复杂问答、附件总结
多模态/视觉qwen3-vl-32b-instruct文本 + 图片可用GPUStack vLLM (2×H100, tp2)图片理解、视觉问答、多模态分析
语音识别 (ASR)funasr (sensevoice)音频转文字可用FunASR pod (CPU)语音转写、语音→LLM 级联回答
流式对话同文本/视觉SSE + WebSocket可用stream-service pod实时逐字输出、实时语音流

3. 文本场景

文本对话使用 deepseek-r1-distill-qwen-32b（推理模型，输出可能含推理过程）。

3.1 非流式（curl）

curl http://192.168.0.151:30080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-r1-distill-qwen-32b",
    "messages": [
      {"role": "user", "content": "请用三句话解释 Kubernetes 调度。"}
    ],
    "max_tokens": 512,
    "stream": false
  }'

3.2 Python（openai SDK）

from openai import OpenAI

client = OpenAI(
    base_url="http://192.168.0.151:30080/v1",
    api_key="not-needed",  # OpenClaw API 无需 key, SDK 字段必填, 任意值即可
)

resp = client.chat.completions.create(
    model="deepseek-r1-distill-qwen-32b",
    messages=[{"role": "user", "content": "请用三句话解释 Kubernetes 调度。"}],
    max_tokens=512,
)
print(resp.choices[0].message.content)

3.3 返回示例

{
  "id": "chatcmpl-...",
  "model": "deepseek-r1-distill-qwen-32b",
  "choices": [
    {"finish_reason": "stop", "index": 0,
     "message": {"role": "assistant", "content": "..."}}
  ],
  "usage": {"prompt_tokens": 10, "completion_tokens": 64, "total_tokens": 74}
}
deepseek-r1-distill-qwen-32b 是推理模型，content 可能含内联推理文本。proxy 默认 STRIP_REASONING_TAGS=true 会剥离 <think>...</think> 标签块；GPUStack 当前返回内联推理（无标签），此时剥离不作用，content 含推理过程（非空即正常）。

4. 多模态 / 视觉场景

图片理解使用 qwen3-vl-32b-instruct。两种方式：① 直接指定视觉模型；② 发文本模型 + 图片，proxy 自动检测图片切到视觉模型（推荐，调用方无需关心）。

4.1 直接指定视觉模型

curl http://192.168.0.151:30080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3-vl-32b-instruct",
    "messages": [{
      "role": "user",
      "content": [
        {"type": "text", "text": "请描述这张图片的主要内容。"},
        {"type": "image_url", "image_url": {"url": "http://192.168.0.151:30080/v1/minio/openclaw-test/test_image.png"}}
      ]
    }],
    "max_tokens": 256
  }'

4.2 自动切视觉模型（推荐）

发文本模型 deepseek-r1-distill-qwen-32b + 图片，proxy 检测到 image_url 自动切到 qwen3-vl-32b-instruct，并把外部图片 URL 下载转 base64（vLLM 直连需 data URI）。

curl http://192.168.0.151:30080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-r1-distill-qwen-32b",
    "messages": [{
      "role": "user",
      "content": [
        {"type": "text", "text": "图里有什么?"},
        {"type": "image_url", "image_url": {"url": "http://192.168.0.151:30080/v1/minio/openclaw-test/test_image.png"}}
      ]
    }],
    "max_tokens": 128
  }'
image_url.url 可用：① 经 MinIO 代理的 URL（如上，/v1/minio/<bucket>/<key>，匿名可读）；② 公网/内网可达的图片 URL；③ data:image/png;base64,<BASE64> data URI。proxy 会下载外部 URL 转 base64 再转发 vLLM。

5. 语音场景（ASR）

语音转文字使用 FunASR（sensevoice 模型）。支持音频文件/URL 转写，以及"语音→LLM 级联回答"。

5.1 音频转文字

curl http://192.168.0.151:30080/v1/audio/transcriptions \
  -F 'file=http://192.168.0.151:30080/v1/minio/openclaw-test/speech_test.wav'
{"text": "你好这是一个语音识别的端到端测试请确认你能听懂我说的话"}

5.2 语音→LLM 级联（音频附件）

用 /v1/chat/completions 的 attachments 字段传音频 URL，proxy 先 ASR 转写，再把转写文本拼入 prompt 送 LLM 回答。

curl http://192.168.0.151:30080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-r1-distill-qwen-32b",
    "messages": [{"role": "user", "content": "请根据以下语音内容回答问题"}],
    "attachments": [{"type": "audio", "url": "http://192.168.0.151:30080/v1/minio/openclaw-test/speech_test.wav"}],
    "max_tokens": 256
  }'

6. 流式场景

6.1 SSE 流式对话（HTTP）

/v1/chat/completions 设 "stream": true，返回 text/event-stream，逐 token 输出。

curl -N http://192.168.0.151:30080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-r1-distill-qwen-32b",
    "messages": [{"role": "user", "content": "讲个短故事"}],
    "stream": true,
    "max_tokens": 256
  }'

每个 chunk：data: {"choices":[{"delta":{"content":"..."}}]}，结束：data: [DONE]

6.2 WebSocket 流式对话（/v1/stream/ws）

双向 WebSocket，适合交互式对话。连接后发 JSON 文本消息，后端流式回 LLM 文字。

ws://192.168.0.151:30080/v1/stream/ws?model=deepseek-r1-distill-qwen-32b
// 客户端 → 服务端
{"type": "text", "content": "你好,请简短回复"}

// 服务端 → 客户端 (流式)
{"type": "llm_chunk", "content": "你"}
{"type": "llm_chunk", "content": "好"}
{"type": "llm_done",  "content": "你好!..."}

6.3 WebSocket 实时语音流（/v1/stream/asr）

实时语音流式 ASR + LLM。前端推 16kHz/16bit/mono PCM 裸数据，后端 FunASR 实时转写并可选自动 LLM 回答。

ws://192.168.0.151:30080/v1/stream/asr
// 1. 客户端连上后发配置
{"type": "config", "auto_llm": true, "model": "deepseek-r1-distill-qwen-32b"}
// 2. 收到 {"type":"config_ack"} 后, 持续发送二进制 PCM (3200 字节/块 ≈ 0.1s)
// 3. 服务端流式返回:
{"type": "asr_partial", "content": "部分识别"}
{"type": "asr_final",   "content": "最终识别"}
{"type": "llm_chunk",   "content": "回复片段"}
{"type": "llm_done",    "content": "完整回复"}
// 4. 客户端发 {"type":"stop"} 结束当前会话
PCM 推流：WAV 文件需去掉 44 字节头发裸 PCM；麦克风实时输入用 Web Audio API 采 16kHz/16bit/mono。详见 static/new_dashboard.html 的 pgWSASR 实现。

8.1 deepseek-r1-distill-qwen-32b（文本推理）

项目说明
能力文本推理（推理模型，含思维链）
适用场景代码分析、复杂问答、长文本总结、附件内容总结
GPU 资源2×H100 (tp2)，常驻
性能（实测）单流 ~46 tokens/s；聚合吞吐峰值 ~760 tokens/s @40 并发；低延迟甜点 ≤20 并发（TTFT < 1s）
限制上下文 max_model_len ≈ 8192（GPUStack 当前配置，原生支持 128k）；输入超 8k 报 400

8.2 qwen3-vl-32b-instruct（视觉）

项目说明
能力文本 + 图片理解（支持 image_url）
适用场景图片问答、截图分析、视觉内容总结、多模态推理
GPU 资源2×H100 (tp2)，常驻
性能（实测）单流 ~34 tokens/s；聚合吞吐峰值 ~660 tokens/s @80 并发
限制图片不宜过小（1×1 会被 vLLM 拒绝，建议 ≥64×64）；图片大小/并发受 vLLM 配置约束

10. 支持与反馈

使用中遇到问题，或有新模型、新能力、配额提升等需求，可联系 OpenClaw 团队反馈。

反馈问题时请尽量提供：

  • 模型名称与调用场景（文本/视觉/ASR/流式/附件）
  • 请求时间、请求 ID（响应 id）
  • 输入规模（token 数、图片大小、音频时长）
  • 错误信息或异常现象（如 404 / 400 / connection refused）
  • 是否流式、是否经 OpenClaw API（:30080）还是直连 LiteLLM
  • 最小请求示例
排错速查：图片 404 → MinIO bucket/对象缺失，跑 scripts/minio_setup.py 灌入；长输入 400 → 超 max_model_len(~8k)；connection refused 192.168.0.151 → GPUStack 瞬态（worker 重启），稍候自愈；模型 not found → LiteLLM 未注册，跑 scripts/register-models-incluster.sh。详见 docs/SERVER_DEPLOY_HANDOFF.md。
